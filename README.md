# ask-ui 利用マニュアル

## 1. 概要

ask-ui は、Claude Code が利用者に行う質問、議論、調査の報告、UI を使った説明を、決まった書式で出すプロジェクトスキルです。ブラウザでないと見せられない図表があるときは、ブラウザの窓に表示します。

| 種類 | 使う場面 | 答え方 |
| --- | --- | --- |
| 質問 | 1 つに決めてほしいとき | 単一選択、複数選択、自由記入 |
| 議論 | 結論を急がず、論点を深めたいとき | 自由記入だけ(選択肢はありません) |
| 報告 | 調査の結果を、表や図つきで読みたいとき | 答えは求めません。読み終えたら「閉じる」を押します |
| 説明 | UI を使って、わかりやすく説明してほしいとき | 答えは求めません。読み終えたら「閉じる」を押します |

- 表示できるもの: 表、簡単な図(SVG)、mermaid の記述から作る図(手順、状態、やり取り、構造、データの関係)、画面デザインのモック
- 1 回に表示できる質問と議論: 1〜4 件(質問だけ、または議論だけ。混在はしません)
- 保存: 質問、議論、報告、説明は、利用者が指示したときだけ、HTML のファイルとして保存できます(「2.4 保存」)
- 導入: [INSTALL.md](./INSTALL.md) を参照してください

質問と議論は、文字だけで足りるものも含めて、すべて ask-ui の書式(決めること、現状、問題点、あるべき姿、推奨、選択肢)で出されます。出し方は 2 つあります。

- 画面: ブラウザでないと表示できない図表(SVG、mermaid の図、画面のモック)がつくときは、ブラウザの窓に表示されます。1 回の質問や議論の中に、1 つでも画面が要る図表があれば、その回の全体が画面で出ます
- 文章版: 表と文章だけ、または文字の図だけのときは、同じ書式をチャットの文章で表した「文章版」で出され、番号で答えます。文字の図で足りるのは、分岐とループがなく、要素が 1 列で 6 個以下の図です(3 手順の流れは文字の図、8 手順の流れや分岐のある図は画面)

ブラウザが使えないなどの技術的な失敗のときは、図表がついていても、文章版で出されます(`AskUserQuestion` は、指示したときだけ使われます)。「画面で」「文章で」と指示すれば、指示が優先されます。案を示して承認を求める提案は質問、意見をもらう提案は議論、承認を求めない提案は説明として出されます。報告と説明は、ブラウザでないと表示できない図表がつくときだけ画面に表示され、表と文章だけのときは、ふつうの返答で出されます。ツールの実行の許可を尋ねる権限の確認は、対象外です。

## 2. 使い方

1. Claude Code に、作業を依頼します
2. Claude が、質問、議論、報告、説明をする場面になると、図表の内容に応じて、ブラウザの窓が開くか、チャットに文章版が出ます。以降は、窓が開いた場合の手順です
3. 画面を、上から順に読みます
    - 質問: 質問ごとに、選択肢を選びます。選択肢に合う答えがない場合は、自由記入欄に書きます。画面下の「送信」を押します
    - 議論: 自由記入欄に、意見を書きます(必須)。画面下の「送信」を押します
    - 報告、説明: 答えは求められません。読み終えたら、画面下の「閉じる」を押します(「2.3 報告・説明の画面」)
4. 質問と議論の回答が、Claude に渡り、窓が閉じます

### 2.1 画面の見方

- 回答が足りないまま送信すると、「エラー: …」の文が出ます。選択肢を選ぶか、自由記入を入力してください
- 「推奨」: Claude が勧める選択肢です。先頭に表示されます
- 質問は、次の見出しで、上から順に並びます。結論(推奨)を先に読んでから、選択肢で比べられます。
    - 決めること: 何を決めるか、意義と狙い、重要度(必須か任意か。根拠と期限)、きっかけ(出所と、根拠の確かさ)を含む、1 つの文章です
    - 1. 現状: 概要と、決定済みの事項と反映先を含む文章です。原文がある場合は、その下に、引用の見た目で出ます
    - 2. 問題点: 現状の問題、または引き起こす問題の文章と、図表(表、流れ図、画面案(モック)など。ない場合は、その理由)です
    - 3. あるべき姿: 成果物の利用者が喜ぶ姿(項目名はつけず、本文だけ)と、採用するときの注意事項です。答えてほしい観点も、ここに含まれます
    - 4. 推奨: 「推奨案：」の行(先頭の選択肢)と、最適である理由、修正イメージを含む文章です。判断の材料が足りないときは、「推奨案：なし」と、示せない理由、判断に必要な情報を含む文章が書かれます
    - 5. 選択肢(2〜4 件): 案ごとに、内容、効果、実現の可否、リスク・デメリット、あるべき姿との一致(高、中、低と、その理由)です。推奨以外の案には、「推奨との違い」もあります
- 議論は、選ばずに、自由記入で意見を返します。次の見出しで、上から順に並びます。
    - 議論したいこと(論点と、意義と狙い、重要度、きっかけを含む文章)、1. 現状、2. 問題点、3. あるべき姿(質問と同じ)
    - 4. 叩き台(2〜4 件): 選ばずに、比べる案です。内容、効果、リスク・デメリット、あるべき姿との一致、未解決の点です
    - 5. 見立て: 仮の結論、根拠、まだ分からないこと、確信の度合い(高、中、低)です。推奨とは違い、議論の出発点です
    - 6. ご意見: 書いてほしい観点が示されます。自由記入は必須です
- 「戻せない可能性：」: 案を実行すると、元に戻せないもの(ファイルやデータの削除、データの書き換え、外部への送信や公開、未コミットの変更の上書き)があるときだけ、「リスク・デメリット」の先頭に書かれます。書かれていなくても、戻せることを保証するものではありません。戻せるかどうかは、お使いの環境(git のコミット、バックアップの有無)で変わります
- 「エラー: …」: 未回答の質問があるときに、その質問の下に表示されます
- mermaid の図: 手順の流れ、状態の移り変わり、やり取りの順序、部品の構造、データの関係などを、記述から作った図です。対応する図は、フローチャート、状態、シーケンス、クラス、ER、XY の 6 種です。ガント、円グラフ、マインドマップなどには、対応していません。
    - 図の下の「元の記述を表示」を開くと、図のもとになった記述が読めます(閉じた状態から始まります)。図が正しいか、見比べるときに使います
    - 図にできない記述(対応外の種類、綴りの誤りなど)は、図の代わりに、「図にできなかったため、記述をそのまま表示しています」という旨と、理由、記述の原文が、最初から開いた状態で出ます。回答や読むことは、そのまま続けられます
    - 保存したファイルにも、同じ図と、「元の記述を表示」が残ります。スクリプトも、外部への通信も、含みません

### 2.2 回答に時間がかかる場合

回答の待機に、総時間の上限はありません。数時間後に答えても、そのまま受け取ります。

### 2.3 報告・説明の画面

図表(SVG、mermaid の図、画面案)がつく調査の報告や、UI を使った説明を頼むと、題名と本文が、ブラウザの窓に表示されます。回答欄はありません。表と文章だけのときは、ふつうの返答で出され、窓は開きません。

- 読み終えたら、画面下の「閉じる」を押します。窓の × で閉じても、同じ扱いです(保存のチェックは、閉じた時点の状態が使われます)
- 窓を開いたまま、続けて Claude に質問できます
- 本文のスクリプトと外部への通信は、実行されません
- 本文にも、mermaid の図が入ることがあります。見方は、2.1 の「mermaid の図」と同じです
- 報告は、結論から始まり、理由・根拠、確認できなかったことが続く構成で書かれます。説明は、「ひとことで言うと」から始まります。これは推奨の構成で、内容によっては、別の構成になります
- ブラウザ全体を閉じた場合は、保存せず、その旨が伝えられます。作業は止まりません

### 2.4 保存

保存は、利用者が指示したときだけ行われます。指示の方法は 2 つあります。

- 画面のチェックボックス: 報告は「この報告を保存する」(既定はチェックあり)、説明は「この説明を保存する」(既定はチェックなし)、質問は「この質問を保存する」(既定はチェックなし)。チェックを入れたまま閉じる(質問は送信する)と、保存されます。質問の窓を閉じる中断のときは、保存されません
- チャットの指示: 「保存して」と伝えると、窓を閉じなくても、その場で保存されます。保存済みのものは、窓を閉じても、二度目の保存はされません

保存先とファイル名は、プロジェクトの規則(CLAUDE.md など)か、利用者の指示に従います。決まっていないときだけ、保存先が ask-ui で聞かれます(同じ会話では聞き直しません)。規則も指示もない場合に限り、作業フォルダ直下の `reports/` を、保存先の候補(推奨)として示します。既存のファイルは上書きされません。同名のときは、名前を変えて保存されます。

保存したファイルは、単独で開ける HTML で、操作部品とスクリプトを含みません(題名の下に、種別と作成日時が入り、印刷にも向きます)。質問の保存では、自由記入に機密情報らしい文字列があると、その部分だけが「機密情報らしい文字列のため、保存から除外した」に置き換わります。

## 3. 画面が表示されない、または中断される場合

| 状況 | 動作 |
| --- | --- |
| 票が規則を満たさない | 画面に出さず、不足している項目を Claude に返します |
| 古い形式(機能 001)の質問票 | 画面に出さず、古い形式であることと、新しい書式の項目名を Claude に返します |
| 票や報告に、機密情報らしい文字列がある | 画面に出さず、Claude が取り除いて作り直します(3 回まで) |
| 窓を開けない(ポップアップのブロックなど) | 質問と議論は、失敗を伝え、ask-ui の書式を文章で表した文章版で出します(ブラウザを操作する部品が動いていないときは、表示を試みる前に文章版で出します)。報告と説明は、文章版にはせず、本文を文章で要約して渡します |
| 回答前に、質問と議論の窓を閉じる | 中断し、作業を止めます。1 秒程度で検知します。保存はされません |
| 回答前に、管理用ページやブラウザ全体を閉じる | 中断し、作業を止めます。検知に、最大で 300 秒かかる場合があります |
| 報告・説明の窓を、× で閉じる | 「閉じる」と同じ扱いです。保存のチェックは、閉じた時点の状態が使われます。作業は止まりません |
| 報告・説明の表示中に、ブラウザ全体を閉じる | 保存せず、その旨が伝えられます。作業は止まりません |

質問と議論の窓を閉じて中断した場合、文章版にも、従来の質問にも、自動の切り替えはしません。

文章版は、失敗のときだけでなく、図表が画面を要しないときの通常の出し方でもあります。通常の出し方では、「ask-ui を使えないため」の通知は付きません。

文章版の質問には、選択肢の番号で答えます(複数問は「問 1: 2、問 2: 1, 3」の形。自由記入も受けます)。文章版の議論には、自由に返信します。文章版の代わりに、ボタンで選べる `AskUserQuestion` を使いたいときは、そう指示してください。

## 4. 注意事項と既知の制約

- 窓を表示しない設定(`--headless`)では使えません。chrome-devtools-mcp は、窓つき(既定)で動かしてください
- 質問の表示中は管理用ページ(別の窓)と質問用の窓の 2 つが開きます。どちらも回答後に閉じます
- 管理用ページは最小化されず、表示されたままです。最小化するには、chrome-devtools-mcp の起動設定に `--chrome-arg=--start-minimized` を追加する方法が考えられますが、質問用の窓も最小化されたまま開く恐れがあり、未検証です
- ブラウザが最初から開いている空の窓は、ツールの仕様で閉じられず、残ります
- 報告・説明の窓を開いている間は、待機が続き、同じブラウザへの別の操作が、最大で 300 秒、順番待ちになります。待機を止めても、順番待ちは解消しません。このため、保存先が決まっていないときの保存先の質問は、ask-ui ではなく、`AskUserQuestion` で行われます
- 回答は、利用者が保存を指示したときだけ保存されます(「2.4 保存」)。指示がなければ、チャットにだけ残ります
- 表、図、モックは、スクリプトの実行と外部への通信を禁止した枠の中で表示します。モックの中の動作(ホバーや切り替えなど)は、動きません
- 外部のフォントや画像を使うモックは、通信が遮断されるため、代わりの表示になります
- 質問や報告が ask-ui の書式で出るかは、確率的です。Claude がふつうの文章で質問したり、報告を長い文章で書いたりすることがあります。フックを入れると、返答を書き始める前に、毎回、出し方を判断する注意が差し込まれ、書式が使われやすくなります(INSTALL.md の「4. フックを設定する」)。報告・説明で図表がつかないときに窓が開かないのは、仕様です
- Claude の文章は、略称や、Claude が作った呼び名を、初出で完全な形と「(以降、〇〇)」の形で定義してから使う規則で書かれます。定義のない略称や、説明を省いた語に気づいたら、お知らせください。この規則は自動では検査されないため、気づいたときのお知らせが頼りです
- 利用者への呼びかけは、プロジェクトの指示(`CLAUDE.md` など)に利用者の呼称の定義があれば、その呼称で書かれます。定義がなければ、主語を省いた文章で書かれ、「あなた」とは呼びません
