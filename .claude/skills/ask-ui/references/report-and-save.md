# 報告・説明の画面と、保存の手順

`SKILL.md` の「報告・説明の手順」「保存」の詳細。必要なときに読む。

## 報告・説明の書き方

- 入力は `title`(題名)と `body`(本文の HTML)の 2 項目だけ。報告か説明かは、入力ではなく、`build-pages.mjs` の `--kind report|explain` で渡す
- 構成は自由(見出しの有無、節の数を問わない)。質問のような決まった項目(① から ⑥)はない
- 表(`<table>`)、図(`<svg>`)、画面案(見た目だけのモック)を、本文に直接置く。見本は `references/exhibit-examples.md` を参照する
- 本文に、外部リンク、外部の画像、外部フォント、CDN を置かない。保存したファイルを開いたとき、CSP で読み込まれず、表示されない。外部リンクのクリックによる移動は、CSP では止まらない
- 本文のスクリプトとイベント属性は、画面では実行されず、保存では取り除かれる。書かない
- ID、パスワード、API Key、`.env` の内容などの機密情報を、題名にも本文にも入れない
- 本文の末尾が質問の形でも、`Stop` フックの差し戻しの対象にならない(フックが見るのは返答の文章で、本文ではないため)。ただし、利用者に質問したいときは、報告ではなく、質問として表示する
- 説明は、回答を求めない。既定では保存しない(画面の「この説明を保存する」はチェックなし)。報告は、既定で保存する(チェックあり)

### mermaid の図

手順、状態、やり取り、構造、データの関係は、mermaid の記述で書ける。本文の中に、次の形で置く。

```html
<pre class="mermaid">
graph TD
  A[質問票を書く] --> B{検証}
  B -->|合格| C[ブラウザに表示]
</pre>
```

- `<pre>` の `class` に、`mermaid` を含める(`class="mermaid wide"` のように、ほかのクラスの併記は可)。値は、引用符で囲む(引用符のない `class=mermaid` は、図にならない)
- 中身は、mermaid の記述。HTML として正しくするため、`<` は `&lt;`、`&` は `&amp;` と書く(`>` は、そのままでも、`&gt;` でもよい。`-->` は、そのままで正しい)
- 対応する図は、フローチャート、状態、シーケンス、クラス、ER、XY の 6 種。5,000 文字まで。書く前後の確認は、`references/mermaid-notes.md` を読む
- 図の下に、元の記述が、折りたたまれて添えられる。図にできない記述(対応外の種類、綴りの誤りなど)は、検証(`validate-input.mjs --report`)が警告を出し、表示では、図の代わりに、原文が展開される。**警告は、拒否ではない**(終了コードは 0)。警告が出たら、記述を直して、もう一度、検証する
- mermaid のコードを、図にせず、例として見せたいときは、`class` に `mermaid` を含めない(例: `<pre><code class="language-mermaid">…</code></pre>`)。このとき `<pre class="language-mermaid">` も、図にならない
- 保存したファイルにも、同じ図と折りたたみが残る。スクリプトも、外部への参照も、含まない

### 推敲

題名と、タグを含まない文章は、`polish.mjs` で整えてよい(`SKILL.md` の「推敲」)。タグで始まる行は、推敲の検査で保護された塊として扱われ、文章としては検査されない(research.md の T008)。このため、 **タグを含む本文は推敲を飛ばし、原文のまま使う** 。終了コード 3(推敲を実行できなかった)のときも、飛ばして表示し、失敗したことをチャットで伝える。

## 機密情報の検出と、作り直し

`validate-input.mjs --report` が終了コード 1 で、「機密情報らしい文字列を検出」と示した欄(`title` または `body`)から、機密情報を取り除いて、`report.json` を作り直す。「機密情報らしい文字列を取り除いて、報告を作り直した」旨をチャットに 1 行伝える。 **作り直しは 3 回まで** 。3 回作り直しても検出される場合は、表示を止めて、利用者に伝える。質問には切り替えない。

## 窓が開かなかったとき

`ASKUI_OPENFAIL` のとき、`AskUserQuestion` へは切り替えない(報告は質問ではないため)。失敗を伝えて、本文を文章で要約して渡す。

## 待機と、読んでいる間の会話

- 報告・説明の窓を開いたあとの待機(`wait_for`)は、バックグラウンドで続ける。その間も、利用者の続きの質問に答えてよい
- 待機中は、同じブラウザへの別の操作が順番待ちになる。`ASKUI_DONE` の通知が来たら、保存と後片付けを行う
- ブラウザ全体や管理用ページが閉じられたとき(`wait_for` の時間切れの後の `list_pages` に管理用ページがない)は、チェックの状態が不明のため、 **保存せず** 、その旨をチャットで伝える。作業は止めない

## 結果の読み方

`ASKUI_DONE` の `askui-result` は、`{"status":"reported","save":<真偽値>,"closedBy":"button"|"window"}`。窓の × で閉じた場合も `ASKUI_DONE`(`closedBy:"window"`)で、`save` は閉じた時点のチェックの状態。

## 保存

### 保存するとき

- 画面のチェック: 結果の `save` が真のときだけ保存する。偽なら保存しない
- チャットの指示(「保存して」など): 窓を閉じなくても保存できる(下の「チャットからの保存」)

### 保存先と名前を決める順序

1. プロジェクトの規則(CLAUDE.md など)や、利用者の指示があれば、それに従う
2. 同じ会話の中で、一度保存先が決まっていれば、聞き直さない
3. どちらもなければ、保存先だけを ask-ui で聞く。選択肢は「作業フォルダの直下の `reports/`(推奨)」「保存しない」と、自由記入(別の場所)
4. 聞いても答えが得られない(窓を閉じたなど)ときは、保存せず、チャットで伝える。作業は止めない

保存先が分かっているときは、`build-pages.mjs` の `--save-to <表示用の文字>` で画面に示す。保存にも同じ値を使う。このスキルとスクリプトには、特定のフォルダ名や名前の規則を書かない。

### 呼び出し

```bash
# 報告・説明
node "${CLAUDE_SKILL_DIR}/scripts/save-html.mjs" --report <作業フォルダ>/report.json --kind report --dir <保存先> [--prefix <名前の先頭>] --work-dir <作業フォルダ>

# 質問(回答つき)。answers.json は、askui-result の内容をそのまま書いてよい
node "${CLAUDE_SKILL_DIR}/scripts/save-html.mjs" --question <作業フォルダ>/questions.json --answers <作業フォルダ>/answers.json --title "<先頭の質問の題名>" --dir <保存先> [--prefix <名前の先頭>] --work-dir <作業フォルダ>
```

成功すると、書き込んだファイルの絶対パスが標準出力に 1 行出る。質問の自由記入に機密情報らしい文字列があると、保存では「機密情報らしい文字列のため、保存から除外した」に置き換わり、標準エラー出力に `置き換えた自由記入: <questionId>` だけが出る。置き換えがあれば、その旨をチャットで 1 行伝える。

### 終了コードの扱い

| コード | 意味 | 扱い |
| --- | --- | --- |
| 0 | 保存した | 保存先をチャットで伝える |
| 1 | 入力の不正 | 内容をチャットで伝える。作業は止めない |
| 2 | 書き込みの失敗 | 失敗をチャットで伝える。作業は止めない |
| 3 | 同名のファイルがある | 名前の規則に通し番号があれば進め、なければ末尾に `-2` などを付けて(`--prefix` か `--title` を変えて)再試行する |
| 4 | 保存済み(`saved.txt` がある) | 保存せず、標準出力のパスを、保存先として伝える |

保存は、後片付け(作業フォルダの削除)の **前** に行う。保存先と成否は、チャットで伝える。

## 質問の保存

- `answered` かつ `save:true` のときだけ保存する。窓の閉鎖(`ASKUI_CLOSED`)のときは、`save` の値によらず、何も保存しない
- 回答を `answers.json` に書き(`askui-result` の内容)、作業フォルダ(`questions.json`)の削除の前に、`save-html.mjs --question` で保存する
- 置き換えがあれば、`questionId` だけをチャットで 1 行伝える

## チャットからの保存

基本は、 **「保存して」と頼まれたら、確認を挟まず、その場で保存する** こと。

1. 報告・説明の窓が開いている間: 窓を閉じずに、作業フォルダの `report.json` から保存する(`--work-dir` を付ける)
2. 質問の窓が回答待ちのとき: その場で質問票を、`--answers` なしで保存する(回答の欄は「未回答」)。回答が送信されたら、`--update` で同じファイルに回答を加える。回答なしで窓が閉じられたときは、質問票だけが残る
3. `ASKUI_DONE` が `save:true` で届いたら、保存の前に、作業フォルダの `saved.txt` を確かめる。あれば、保存せず、保存済みであることを伝える(`--work-dir` を付けた呼び出しは、終了コード 4 で止まる)
4. 窓を閉じたあと(作業フォルダの削除後)の指示では、会話に残る内容から `report.json`(質問は `questions.json` と `answers.json`)を作り直して保存する。すでに保存したことを覚えているときは、保存せず、保存先を伝える
5. ブラウザ全体が閉じられても、チャットの指示は有効
6. 保存先が決まっていないときだけ、保存先を聞く。待機中は、ほかのブラウザ操作が、待機の残り時間(最大 300 秒)の間、順番待ちになる。`TaskStop` で待機を止めても、ブラウザは解放されない(research.md の U7)。このため、待機中は、ask-ui ではなく、`AskUserQuestion` で保存先を聞き(待機を続けたままでよい)、答えを受けたら保存する。保存は Bash の操作で、順番待ちにならない。そのあとは、通常どおり、「閉じる」の通知を待つ

別のファイルとして保存し直す指示が、利用者から明示されたときだけ、`--again` を付ける。

画面のチェックボックスは、チャットで保存したあとも、保存済みと表示されない。
