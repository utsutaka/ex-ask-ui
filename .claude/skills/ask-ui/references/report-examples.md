# 報告と説明の見本

`references/report-and-save.md` の「推奨の型」に沿った、検証に合格する例。`report.json` の `title` に題名、`body` に html を入れる(JSON の文字列にするときは、改行を `\n`、引用符を `\"` にする)。題材を書き換えて使う。

どちらの見本も、先頭の節は、略称を使わず、完全な形で書いている。縮めた語は、初出で完全な形を書き、直後に「(以降、〇〇)」と定義している(`SKILL.md` の「文章の書き方(共通)」)。

## 報告の見本

調べたことと、その結果を伝える。結論から始まり、理由・根拠、確認できなかったことが続く。

題名: 文章の規則を、自動で検査できるか

```html
<h2>結論</h2>
<p>文章の規則は、自動では検査できません。縮めた語が、定義のない略称か、本エージェントが作った呼び名かは、意味を読まないと見分けられず、文字の形で拾う方法は、誤検出と拾い漏れが多いためです。そのため、見本、書き終えた後の見直し、運用での聞き返しの記録で担保します。</p>

<h2>理由・根拠</h2>
<h3>文字の形で拾うと、正しい語を拾い、造語を拾い漏らす</h3>
<p>略称の目印を、英字と数字の並びにすると、Generator による1回目の生成(以降、G1生成)のような略称は拾えます。しかし、<code>UTF-8</code> のような正しい固有名詞も拾います(誤検出)。一方、顧客の体制や予算感を指す「顧客リソース」のような日本語の造語は、形に特徴がなく、拾えません(拾い漏れ)。</p>
<table>
<thead><tr><th>語</th><th>種類</th><th>形で拾えるか</th></tr></thead>
<tbody>
<tr><td><code>UTF-8</code></td><td>正しい固有名詞</td><td>拾う(誤検出)</td></tr>
<tr><td>G1生成</td><td>定義のない略称</td><td>拾う</td></tr>
<tr><td>顧客リソース</td><td>定義のない造語</td><td>拾えない(拾い漏れ)</td></tr>
</tbody>
</table>

<h3>誤検出の多い検査は、読まれなくなる</h3>
<p>推測です。警告が正しい語にも出ると、警告を読まなくなり、本当に直すべき語も見過ごされます。</p>

<h2>前提・現状</h2>
<p>この規則は、文章の書き方の共通規則を定めた機能(機能 005)の共通の節に書かれています(<code>SKILL.md</code> の「文章の書き方(共通)」)。検証(<code>validate-input.mjs</code>)は、この規則を理由に、票や報告を拒否も警告もしません。</p>

<h2>確認できなかったこと</h2>
<p>文字の形で拾う検査を実際にかけたときの、誤検出と拾い漏れの件数は、測っていません。「理由・根拠」の説明は、理由の推論であり、測定の結果ではありません。</p>

<h2>次にできること</h2>
<p>導入後に、聞き返しの記録(うつたかさんが意味を聞き返した語を残すファイル。<code>feedback.md</code>)を読み、実際に起きた語の傾向を見てから、検査を足すかどうかを決められます。</p>
```

## 説明の見本

仕組みや使い方を伝える。「ひとことで言うと」から始まり、全体像、詳細、例が続く。

題名: 質問と議論の違い

```html
<h2>ひとことで言うと</h2>
<p>質問は、案を選んで答えてもらうものです。議論は、案を選ばず、自由記入で意見をもらうものです。</p>

<h2>全体像</h2>
<pre class="mermaid">
graph TD
  A[利用者に決めてほしいことがある] --> B{案を1つに決めたいか}
  B -->|はい| C[質問: 選択肢から選んでもらう]
  B -->|いいえ| D[議論: 論点を深め、自由記入で意見をもらう]
</pre>

<h2>詳細</h2>
<h3>質問</h3>
<p>決めること、現状、問題点、あるべき姿、推奨、あなたの選択の順に表示されます。選択肢から選ぶか、自由記入で答えます。推奨は、先頭の選択肢の名前が表示されます。</p>
<h3>議論</h3>
<p>議論したいこと、現状、問題点、あるべき姿、叩き台、見立て、ご意見の順に表示されます。選ばずに、自由記入だけで答えます。叩き台は2〜4件で、選ばずに比べます。見立ては、選ばせるための推奨ではなく、議論の出発点となる仮の結論です。</p>

<h2>例</h2>
<p>設定ファイルの形式を1つに決めるときは、質問です。設定の管理方針を、結論を急がずに話し合うときは、議論です。</p>

<h2>つまずきやすい点</h2>
<ul>
<li>推奨を示せないときも、選んでほしいなら質問です。そのときは「推奨案：なし」と書きます。</li>
<li>1回の表示は、質問だけ、または議論だけです。混ぜて表示できません。</li>
</ul>
```
