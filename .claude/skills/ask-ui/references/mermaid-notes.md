# mermaid の記述で、エラーや表示の不正になる条件

mermaid の記述(`kind: "mermaid"` の `source` と、報告・説明の本文の `<pre class="mermaid">`)を書く前と、書いた後に、読む。書き方の見本は、`references/exhibit-examples.md` にある。

ここに載せるのは、**再現を確認した条件だけ**である(確認した日付と、変換の部品の版を、表に書く)。新しい条件が分かったら、再現を確認してから、表に足す。

## 書く前に

1. 先頭の行で、図の種類を宣言する。対応する図は、次の 6 種:フローチャート(`graph`、`flowchart`)、状態(`stateDiagram-v2`)、シーケンス(`sequenceDiagram`)、クラス(`classDiagram`)、ER(`erDiagram`)、XY(`xychart-beta`)
2. ガント、円グラフ、マインドマップなどは、対応していない。時間の配分や割合は、表(`table`)か、`svg` で示す
3. subgraph には、英数字の ID と、角括弧の見出しを付ける(`subgraph IN[入力]`)
4. 1 つの記述は、5,000 文字までにする。長くなる場合は、図を分ける

## 書いた後に

1. 票(または報告)を検証する。検証の出力に **警告** が出たら、下の表で、該当する条件を探し、記述を直して、もう一度、検証する。警告には、直す場所(票の項目の番号、または、本文の何番目の要素か)と、部品のエラーの内容が書かれている。直せない場合、または、直さないと決めた場合は、そのまま表示してよい(表示では、図の代わりに、原文が展開される)
2. 警告が出なくても、構文の誤りが、見つからない場合がある(下の表の「壊れた構文」)。表示される図と、折りたたんだ元の記述を、見比べられるように、記述の矢印の両端と、括弧の対応を、読み返す
3. subgraph の名前の重複は、検証も警告も、見つけない。subgraph に、英数字の ID を付けたかを、読み返す
